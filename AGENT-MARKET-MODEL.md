# OpenAutonomyX Agent Market Model

The OpenAutonomyX agent market model defines how agent offerings are categorized, compared, and selected.

## Purpose

The agent market is large and fast-moving (platforms, frameworks, vertical agents, and embedded agentic features). A shared category model lets offerings be compared and governed consistently.

## Market Segments

- **Agent platforms** — build, run, and govern agents.
- **Agent development platforms** — tooling for engineering agents.
- **No-code / low-code agent builders** — citizen-built agents.
- **Vertical / domain agents** — service, sales, procurement, finance, legal, HR, IT, manufacturing, analytics.
- **Embedded agentic features** — agentic capability inside existing products.
- **Agent marketplaces** — discovery and distribution of agents and capabilities.
- **Agent governance and control** — identity, policy, evaluation, drift, compliance.

## Category Attributes

Each category is defined by: primary buyer, primary use cases, autonomy expectations, integration model, governance needs, and key risks.

## Category Governance

Agent categories are maintained as a governed taxonomy with mappings to external category systems (analyst taxonomies, CNCF AI-native landscape). Categories are versioned; mappings carry confidence and evidence.

## Selection Posture

Market selection weighs adoption, governance, and security together (see the agent protocol model). Offerings are registered as governed `standard` or provider objects before adoption.

## Market Principle

A category is a lens for comparison and governance, not a marketing label. Buy by use case and governance fit, not by hype.
